You are building the public-facing marketing website for Beacon, a predictive open source dependency health monitoring platform. This is a separate Next.js project from the app dashboard — it is the site a visitor lands on before they sign up. It includes a landing page, a pricing page, and all supporting sections. The stack is Next.js 14 App Router, TypeScript, Tailwind CSS, Framer Motion for animations, and Lucide React for icons. No backend, no auth, no API calls — this is a pure static marketing site with mock content.

Responsive behaviour — applies to every component
All sections use a max-width container of 1200px (1100px for pricing, 900px for comparison table) centred with mx-auto. Horizontal padding is px-6 on mobile, px-8 on desktop. Grid layouts use Tailwind responsive prefixes: grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 and so on — never hardcode column counts without responsive variants. The nav collapses to a hamburger below md breakpoint. Font sizes scale down on mobile: hero headline 56px→36px, section headings 36px→26px, all others remain the same. Touch targets on mobile are minimum 44px height.

Animation rules — Framer Motion
Every section uses useInView from Framer Motion with once: true and margin: "-80px" so animations fire once as the section scrolls into view, not on page load. The standard entrance pattern is initial={{ opacity: 0, y: 16 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.28, ease: 'easeOut' }} applied to the section wrapper. Child elements stagger using variants with staggerChildren. Never animate layout properties like width, height, or padding — only opacity, x, y, scale, and rotate. The pricing card billing toggle animates price text with AnimatePresence. The FAQ accordion animates height with motion.div wrapping the answer content.
